## Headlines

- **XTX Markets grants $10mn each to Lean FRO and the Mathlib Initiative.** XTX Markets announced $10mn to Lean FRO, a focused research organisation run by Convergent Research, and $10mn to the Mathlib Initiative, each covering core operating costs to 2030. XTX Markets says Lean provided the verification layer in the auto-formalisation of Fermat's Last Theorem. ([xtxmarkets.com](https://www.xtxmarkets.com/news/2026-update-on-xtx-markets-ai-philanthropy/))
- **Anthropic's Claude formalizes a complete proof of Fermat's Last Theorem in Lean.** Working largely autonomously over 11 days, Claude wrote 13 million lines of Lean (over 5x the size of Mathlib, the principal community library) and proved 29,500 intermediate theorems. Kevin Buzzard compiled the code and ran comparator on it, and the full proof is on GitHub with a written walk-through. ([anthropic.com](https://www.anthropic.com/research/formalizing-fermats-last-theorem), [xenaproject.wordpress.com](https://xenaproject.wordpress.com/2026/09/04/flt-anthropic-has-beaten-me-to-it/), [anthropics/fermats-last-theorem](https://github.com/anthropics/fermats-last-theorem), [nature.com](https://www.nature.com/articles/d41586-026-02822-9))
- **OpenAI announces Lean-checked singularity in the 3D Navier-Stokes equations.** OpenAI said 10,000 autonomous AI agents found a singularity in the Navier-Stokes equations in three dimensions, with the result formally checked in Lean. Hours earlier, Tristan Buckmaster at New York University and Levent Alpöge at Anthropic reported Lean-verified proofs for three related results, including one for the Euler equations. ([quantamagazine.org](https://www.quantamagazine.org/ai-has-solved-one-of-maths-1-million-millennium-prize-problems-20260908/), [blog.computationalcomplexity.org](https://blog.computationalcomplexity.org/2026/09/navier-stokes-and-lean.html))
- **Lean 4.34.0 fixes three kernel soundness issues found with AI testing.** Lean 4.34.0, released 2026-09-14, fixes three soundness issues found with AI adversarial testing and adds defensive kernel checks. bv_decide gets integrated with sym and grind interactive modes and is up to six times faster, linters can carry state across commands, and lake lint gains a --code-quality mode emitting machine-readable JSON. ([v4.34.0 release notes](https://lean-lang.org/doc/reference/latest/releases/v4.34.0/))
- **Certora proves zlib's inflate_table memory-safe and terminating in Lean.** In under two weeks, Certora built an experimental C-to-Lean pipeline and proved that the Clight (CompCert's C intermediate representation) model of zlib's 266-line inflate_table function is memory-safe and terminating. The proof, around 20,000 lines of Lean, was written almost entirely by LLMs, and the Lean kernel checked every step. ([certora.com](https://www.certora.com/blog/formally-verifying-zlib-memory-safety-with-lean))

## Lean core and ecosystem

- **Lean FRO and SAIR Foundation launch Stage 1 of Lean Kernel Challenge.** The multi-stage competition seeks faster algorithms for verified computation (using the Lean kernel to check computational results in a proof) across eight problems, including Fibonacci, prime counting, Rule 110, and SHA-256. Entrants prove each algorithm matches its specification; submissions close November 20, 2026. ([terrytao.wordpress.com](https://terrytao.wordpress.com/2026/09/16/sair-competition-lean-kernel-challenge/), [competition.sair.foundation](https://competition.sair.foundation/competitions/lean-kernel-challenge))
- **Joachim Breitner announces con-leche, a Lean checker proven consistent.** con-leche is an external checker for Lean, proven in Lean never to accept a proof of False, implemented and proven by Claude (Fable and Opus) under heavy supervision by Joachim Breitner at the Lean FRO. On the FLT proof by Anthropic, it accepted 1,044,222 declarations in 2 h 22 min wall time. ([leanprover/con-leche](https://github.com/leanprover/con-leche), [leanprover.zulipchat.com](https://leanprover.zulipchat.com/#narrow/channel/583339-AI-authored-projects/topic/con-leche.2C.20a.20lean.20checker.20with.20a.20proof.20of.20consistency/with/623085852))
- **Arthur Adjedj proposes a renovation of the Lean kernel logic.** A meta issue by Arthur Adjedj, worked out with @nomeata, plans kernel changes that move feature selection for inductives to the elaborator and aim for a decidable, transitive definitional equality algorithm. Recursive predicates like Acc would lose large elimination, and the kernel changes would ideally ship in a single release. ([lean4#14977](https://github.com/leanprover/lean4/issues/14977))
- **Sebastian Ullrich logs build optimizations for Anthropic's Lean proof of Fermat's Last Theorem.** On a 1,000-module slice, adopting the module system and import minimization cut task-clock to 3,268 s (down 63.1%) and wall-clock to 140 s (down 86.3%). Sebastian Ullrich also released the proof as a single 1.01 GiB .olean download that can be run through lean4export for external checkers. ([hackmd.io](https://hackmd.io/@tKCokyPgR8qHjLvzExSBbw/Byxo8AcdGx), [fermats-last-theorem export](https://github.com/Kha/fermats-last-theorem/releases/tag/export))
- **Lean publishes hex, an aggregator for verified computational algebra libraries.** The leanprover/hex repository bundles the released hex libraries for verified computational algebra in Lean 4, including LLL lattice reduction, integer polynomial factorization, graph canonical labelling via a formalization of nauty, and algebraic numbers. Each computational library is Mathlib-free, with Mathlib correspondence proofs in separate theory libraries. ([leanprover/hex](https://github.com/leanprover/hex))
- **Lean FRO publishes con-ron, a Rust port of the con-leche checker.** con-ron ports con-leche, an external Lean checker with a formal consistency proof, to Rust. It was written by AI under supervision from Joachim Breitner, and its Rust code is proven (partially) correct via an Aeneas-generated model, so checking a proof with both tools guards against compiler or runtime bugs. ([leanprover/con-ron](https://github.com/leanprover/con-ron))
- **Lean runtime now compiles mimalloc in and trims elaboration overhead.** Julia Markus Himmel merged a change that compiles mimalloc as part of the Lean runtime, and Sebastian Ullrich moved rarely-updated Core.Context fields into a cold subobject (mathlib4: -0.82% instructions, -2.03% wall-clock). Lean also updated to mimalloc 3.4.5, fixing a Windows memory leak, and CI changes should halve merge queue run times. ([lean4#15017](https://github.com/leanprover/lean4/pull/15017), [lean4#14982](https://github.com/leanprover/lean4/pull/14982), [lean4#15060](https://github.com/leanprover/lean4/pull/15060), [lean4#15123](https://github.com/leanprover/lean4/pull/15123))
- **Wojciech Nawrocki adds an HTML type and HTML-like syntax to Lean.** Two merged pull requests add `Lean.Data.Html`, a type of HTML forests aimed primarily at authoring HTML, with a renderer that produces a String, plus HTML-like syntax with an elaborator into that type. Companion downstream-lean4 pull requests adopt the type and syntax throughout supported packages. ([lean4#14935](https://github.com/leanprover/lean4/pull/14935), [lean4#15002](https://github.com/leanprover/lean4/pull/15002))

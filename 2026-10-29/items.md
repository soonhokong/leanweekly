## Headlines

- **Troy Lee formalizes László Babai's graph isomorphism algorithm using an AI agent.** With László Pyber's analysis replacing the classification of finite simple groups, the formalization proves that a single-tape Turing machine (Mathlib's Turing.TM0) decides whether two simple graphs are isomorphic within a quasipolynomial number of transitions. The agent (Claude Code, with Claude Opus 5.5) wrote the Lean code from 18 to 29 October 2026. ([palomar-registry.org](https://palomar-registry.org/entry?id=PALOMAR-2026-10-29-000015&version=1), [troyjlee/graph-iso-lean](https://github.com/troyjlee/graph-iso-lean))
- **Anthropic publishes Lean formalization of Claude's refutation of the Exponential Time Hypothesis.** Anthropic's eth/ project, a machine-checked Lean 4 formalization, states that a single deterministic Turing machine counts the satisfying assignments of every k-CNF with at least two clauses on at least four variables, each of which occurs, within a step bound that refutes the hypothesis. Claude's paper is in the project folder. ([anthropics/formal-math](https://github.com/anthropics/formal-math/tree/main/eth))
- **XTX Markets gives £5 million to Imperial College London for Langlands Lab.** The lab for AI-assisted mathematics, led by Kevin Buzzard, will focus on the Langlands program, which seeks connections between fields, particularly number theory and analysis. It aims to produce new results verified in Lean and begins operating in 2027, with the grant supporting five PhD students and three postdoctoral researchers over four years. ([imperial.ac.uk](https://www.imperial.ac.uk/news/articles/admin-services/giving/2026/5-million-grant-to-establish-new-laboratory-for-ai-assisted-mathematics-at-imperial/))
- **Juan J. Manfredi completes Lean formalization of OpenAI's infinity-harmonic estimates.** The formalization, built on Mathlib, proves the main results of OpenAI's 4 October 2026 preprint, including that infinity-harmonic functions (viscosity solutions of the infinity-Laplace equation) on connected open sets in dimensions 3 and higher are C¹, using only Lean's three standard axioms. Claude agents wrote the Lean proofs with Trellis, an AI-assisted formalization pipeline. ([palomar-registry.org](https://palomar-registry.org/entry?id=PALOMAR-2026-10-29-000040&version=1), [na0b/infharmonic-lean](https://github.com/na0b/infharmonic-lean))

## Lean core and ecosystem

- **Leo de Moura speeds up kernel checking of lia and grind proofs.** Lean's lia (cutsat) now shares proofs across grind case splits, for up to 2.8x faster elaboration and up to 200x faster kernel checking on goals with many case splits. Kernel-friendly certificates for lia, grind's ring solver, simp +arith and grind linarith followed; the ring certificates cut kernel instructions by 51.5% across 40 benchmark files. ([lean4#15905](https://github.com/leanprover/lean4/pull/15905), [lean4#15911](https://github.com/leanprover/lean4/pull/15911), [lean4#15943](https://github.com/leanprover/lean4/pull/15943), [lean4#15981](https://github.com/leanprover/lean4/pull/15981), [lean4#15983](https://github.com/leanprover/lean4/pull/15983))
- **Sebastian Graf merged `vcgen +jp`, which verifies code after a split once.** Without `+jp`, `vcgen` copies the code after an `if` or a `match` into every branch, so the number of copies doubles with each consecutive split. With `+jp`, VC generation grows linearly with the number of splits, and the shared code is verified under a hypothesis stating what each branch knows at its end. ([lean4#14398](https://github.com/leanprover/lean4/pull/14398))
- **Leo de Moura makes grind failure messages short by default.** Pull request #15906 made diagnostics opt-in via +verbose, so failures showed only the remaining goal and a hint; collecting and printing diagnostics took about 38% of the time spent on easy failing lia goals. Pull request #16073 shortened the failure message further, naming the invoked tactic, such as lia, without printing the goal. ([lean4#15906](https://github.com/leanprover/lean4/pull/15906), [lean4#16073](https://github.com/leanprover/lean4/pull/16073))
- **Mac Malone opens Lake pull request to reduce build-store contention.** The pending change (#15805) has Lake first fetch transitive artifacts from a single build-store snapshot, falling back to the real build store only when an artifact is missing. Mac Malone also opened #16083 to benchmark Lake's module setup computation, which experiments show is a significant scalability chokepoint in projects with thousands of modules. ([lean4#15805](https://github.com/leanprover/lean4/pull/15805), [lean4#16083](https://github.com/leanprover/lean4/pull/16083))

## Papers, events, press

- **Benjamin Pierce announces Agentic Proof Engineering, a Spring 2027 course at Penn.** The semester course is on building formal proofs about software systems at scale, in collaboration with AI agents, and will also be delivered as a live webinar for participants outside Penn. Some lectures and projects will be phrased in terms of Lean, though fluency with the specifics of Lean will not be needed. ([cis.upenn.edu](https://www.cis.upenn.edu/~bcpierce/agentic-proof-engineering/syllabus.html))
- **GenProof paper on verifying Minecraft redstone circuits uses Lean's bv_decide.** Mike Murunov and Maksim Borisov's gate accepts a redstone layout only with a machine-checkable certificate of equivalence to its Verilog specification. Lean 4 re-proves the claim, unfolding it to one 4-bit equation per node and calling bv_decide, which bit-blasts, runs the CaDiCaL solver and checks its proof with a verified checker. ([paper (pdf)](https://balalaika.ai/projects/redstone-verify/paper.pdf))

Lean core·May 14

Lean publishes Lean Workbench, an experimental online environment for Lean

The leanprover/lean-workbench repository aims to provide familiar (VS Code with the Lean 4 extension) and novel interfaces to Lean online, giving each user an isolated Code Server instance inside a bubblewrap sandbox. The README warns the project is in progress and experimental, with a security audit forthcoming.

⊢Checked against: leanprover/lean-workbench

Lean core·May 5

Sebastian Graf brings Sym-based mvcgen' to parity with mvcgen

A merged Lean pull request by Sebastian Graf gives the Sym-based mvcgen' feature parity with mvcgen, except +jp (join-point handling), at a cost of about 10% vcgen slowdown for cleaner user-visible VCs. A separate change adds whileM, which makes repeat/while loops verifiable with mvcgen.

⊢Checked against: lean4#13578·lean4#13209·lean4#13672·lean4#13582

Lean core·May 14

Lake adds a requiresModuleSystem option to flag non-module imports

Sebastian Ullrich's merged Lean pull request adds the Lake package option requiresModuleSystem: Lake then warns whenever a non-module-system file (one without a module header) imports a module of the package. A separate fix repairs code generation that broke with structures using private fields and types inaccessible in the current scope.

⊢Checked against: lean4#13646·lean4#13679

Lean core·Apr 5

Kim Morrison splits Lean's implicit transparency level into implicit and instances

A merged pull request by Kim Morrison makes the transparency hierarchy none < reducible < instances < implicit < default < all, so @[implicit_reducible] annotations no longer have the side effects @[instance_reducible] has. A separate open pull request by Leo de Moura enables the backward.isDefEq.respectTransparency.types option by default.

⊢Checked against: lean4#13637·lean4#13283

Lean core·May 11

Leo de Moura merges grind improvements for local theorems in Lean

In merged Lean pull requests by Leo de Moura, grind diagnostics now show local hypotheses used as E-matching theorems with their user-facing names and instantiation counters. A new grind option, genLocal, controls the maximum term generation for local theorems (for example, hypotheses) and defaults to 8, the same value as gen.

⊢Checked against: lean4#13699·lean4#13698

Lean core·May 8

Mac Malone merges three Lake fixes, including workspace-level compiled configurations

Compiled Lake configurations such as lakefile.olean now live in the workspace's .lake/config, removing a source of contention between workspaces sharing a dependency. Lake also now includes IR for a meta import's transitive imports, fixing "missing data file" errors with the artifact cache, and all Lake tests are re-enabled by default.

⊢Checked against: lean4#13683·lean4#13600·lean4#13692

Lean core·May 14

Demo previews Rust source references resolved through rust-analyzer

A demo chapter on x80.org previews foreign Rust references backed by a live language-server lookup: resolved references render a compact Rust source link and a grouped Rust code panel fetched from the location returned by rust-analyzer. A reference the language server cannot find is reported as unresolved, without a code panel.

⊢Checked against: x80.org

Lean core·May 7

Wojciech Nawrocki adds collaborative editing to Lean Workbench

Wojciech Nawrocki merged a Yjs-based collaboration server that syncs changes between clients, plus collaborative editing support in the vscode-workbench extension. A separate change makes it impossible for openvscode-server instances to make requests against other instances.

Lean core·Jul 15

Lean v4.33.0 release candidate 1 is out

The Lean developers published release candidate 1 for Lean v4.33.0, which centers on a more responsive editor, automatic try? proof suggestions, improved lia and grind tactics, a Float type that is no longer opaque, and kernel soundness fixes. It also enables backward.isDefEq.respectTransparency.types by default, the change most likely to need attention when porting.

⊢Checked against: v4.33.0 release notes·lean4 v4.33.0-rc1

Lean core·Jul 14

Sebastian Graf adds frame inference and contract syntax to Lean's vcgen

Merged pull requests extend vcgen, described as a verification condition generator over the Std.Internal.Do metatheory, with automatic frame inference and with loop invariants and def contracts (require and ensures clauses) that vcgen discharges automatically. A showcase repository collects imperative Lean programs verified with one 'vcgen ... with finish'.

⊢Checked against: lean4#14389·lean4#14195·sgraf812/vcgen-showcase·leanprover/lean4

Lean core·Jul 13

Lean v4.32.0 makes the new do elaborator the default

Lean v4.32.0 adds the do← marker for effect forwarding and cuts import Mathlib time by about 10% through a DiscrTree insertion fix. Lake's linting framework gains option-based control and module linters, and an experimental incremental-compilation mode lands behind CLI flags.

⊢Checked against: v4.32.0 release notes·lean4 v4.32.0

Lean core·Jul 11

Sebastian Ullrich proposes prefix trees in oleans to speed up Lean imports

An open pull request by Sebastian Ullrich replaces hash maps built at import time with per-module prefix trees precomputed when oleans are written, cutting import Lean wall clock by 28% and mathlib's import phase by 21%, for about 6% larger stdlib oleans. A separate pull request by Sebastian Ullrich upgrading Lean to mimalloc 3 was merged.

⊢Checked against: lean4#14362·lean4#7786

Lean core·Jul 8

Wojciech Różowski adds two-phase stateful linters to Lean

A merged pull request lets linters persist and share state across command elaboration, with each stateful linter running an early phase and a late phase. Wojciech Różowski also changed the UnusedSimpArgs linter hint and split registerParametricAttribute as preparatory work for warning when @[deprecated] points at an already-deprecated declaration.

⊢Checked against: lean4#14357·lean4#14344·lean4#14313

Lean core·Jul 7

Kim Morrison releases first packages of Hex, a computational algebra library

The first Hex packages provide dense matrices, row reduction, Gram-Schmidt, and a verified implementation of the LLL lattice basis reduction algorithm, plus a version that delegates computation to the C library fplll while verifying a certificate. Specifications are written first, then AIs implement code and proofs, and a blog post runs the Coppersmith attack on RSA.

⊢Checked against: kim-em.github.io·kim-em/hex

Lean core·Jul 7

Sebastian Ullrich merges editor whitespace fix and deterministic kernel recursion limit

Lean now reuses tactic results when only whitespace after a tactic changes, so progress is kept when preparing to type the next tactic. The kernel's deep recursion error is now bounded by the maxRecDepth option instead of the physical stack size, which is a breaking change that may require explicit maxRecDepth bumps.

⊢Checked against: lean4#13956·lean4#11958

Verification·Jul 6

Logos Research proves an F# program and its Python rewrite equivalent

In a Logos Research prototype, a deterministic translator turns both the original and the rewrite into Lean, and a theorem prover proves the two compute the same result on every input. For iCPPI, a portfolio-insurance algorithm, the machine-checked proof ran to some 22,000 characters, with floats modelled as exact real numbers.

⊢Checked against: logosresearch.ai

Verification·Jul 2

ArkLib anchors a growing ecosystem of Lean libraries for verifying SNARKs

ArkLib, a project supported by the Ethereum Foundation, mechanizes the probabilistic security proofs that succinct non-interactive arguments of knowledge (SNARKs) depend on. It gives zk engineers and cryptography researchers machine-checked specifications and executable references for proof systems where a single soundness bug can be catastrophic.

⊢Checked against: lean-lang.org

Lean core·Jul 1

Joachim Breitner adds automatic try? suggestions to Lean at common proof sites

A merged pull request by Joachim Breitner makes Lean suggest try? output for empty by blocks, unsolved goals, and sorry tactics, gated by three options that default to off. It replaces the tactic.tryOnEmptyBy option from an earlier pull request with a different implementation.

⊢Checked against: lean4#13830

Mistral AI lists Leanstral 1.5, an updated Lean 4 proving model

Mistral AI's documentation lists Leanstral 1.5, dated June 30, 2026, as an updated Lean 4 formal proof engineering model optimised for automated theorem proving and autoformalization.

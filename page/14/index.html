Lean core·Oct 7

Lean reference manual documents vcgen, the successor of mvcgen in Lean 4.35

A pull request by Sebastian Graf documents the vcgen tactic and its Std.WP framework, adds the tutorial "Verifying Imperative Programs Using vcgen", and moves the mvcgen chapter and tutorial to their own files. The Kraken project already uses vcgen to prove that FFmpeg's FMA3 dot-product loop, over two arrays that may alias, terminates without faulting.

⊢Checked against: reference-manual#927·zrlk/kraken

Lean core·Oct 4

Sebastian Ullrich makes Lean's type class resolution cache persist across commands

Two merged pull requests by Sebastian Ullrich keep type class resolution results for later commands and let queries differing only in free variables share a cache entry. Building Mathlib takes about 4% fewer instructions and 8% less wall-clock time, and spends about 16% less time in type class resolution.

⊢Checked against: lean4#14369·lean4#14316

Google's Gemini 4 Argon writes a Lean-verified quantum arcsin implementation

Google's launch post for Gemini 4 Argon (dated 2026-10-13) reports an arcsin implementation, a building block in recent quantum simulation algorithms, written by Argon and formally verified in Lean. It cuts spacetime cost by more than 100x compared to a published quantum CORDIC baseline.

Verification·Oct 15

Flapjack ports the verified Pancake compiler from HOL4 to Lean

Flapjack is bringing the Pancake compiler, originally verified in HOL4, and its proofs to Lean, with a path compiling a fragment of Pancake to RISC-V where all stages except parsing and AST conversion have a correctness theorem. A MIPS32 backend targets the Ziren zkVM, but its output has been run only on Ziren's Lean model.

⊢Checked against: flapjack-lang.dev

Lean core·Oct 14

Joachim Breitner and Lean FRO describe the proof behind con-leche checker

con-leche, a checker for Lean 4, comes with a proof in Lean that every environment it accepts has a model in set theory, so no accepted environment holds a proof of False. A new document gives a pen-and-paper account of that argument on a simplified fragment of the checker.

⊢Checked against: leanprover.github.io

Lean core·Oct 12

Sebastian Ullrich removes Lean's 255-object-field limit per constructor

A merged pull request by Sebastian Ullrich removes the limit of 255 object fields per constructor, and thus per structure. When a constructor has more, the compiler keeps the first 254 in the constructor object and stores the rest in a chain of spill objects, with one pointer followed per spill object on access.

⊢Checked against: lean4#15516

Lean core·Oct 13

Julia Markus Himmel reworks order instances across Lean core types

Julia Markus Himmel redefined the order on String as the lexicographic order of its UTF-8 encoding, made Min Float follow the IEEE-754-2019 minimum operation, and added missing order instances for BitVec, List, Array, Vector and ByteArray. Sofia Rodrigues fixed leaks and refactored the libuv bindings.

⊢Checked against: lean4#15581·lean4#15257·lean4#15274·lean4#15304·lean4#15329·lean4#15175·lean4#15545

Lean core·Oct 4

Leo de Moura adds option to run grind on Sym.simp normalizer

A merged Lean pull request adds backward.grind.normalizer, which switches grind to the Sym.simp-based normalizer when set to false (the default behavior is unchanged). Related changes add grind_norm, a debugging tactic whose check mode runs both normalizers and fails when results differ, and fix negation-pushing rewrites that had been dead code since #9271.

Lean core·Oct 9

Sebastian Ullrich merges two fixes to how Lean modules export theorems

In Lean, an asynchronously elaborated theorem's exported info in a module is now available as soon as its signature is, instead of after its proof is elaborated. A second change stops modules from exporting constants such as foo.eq_1 realized only inside a proof, so such proofs no longer trigger downstream rebuilds.

⊢Checked against: lean4#15559·lean4#15563

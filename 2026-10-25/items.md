## Headlines

- **Joachim Breitner releases con-agua, a Lean checker with verified x86 assembly.** Written by AI under Joachim Breitner's supervision, con-agua is an x86 assembly port of the external Lean checker con-leche and requires the Kraken x86 semantics to be correct in place of the Lean compiler and runtime. A 5MB assembly file and a 200-line main.c, plus one data file, are all it needs. ([leanprover/con-agua](https://github.com/leanprover/con-agua/), [leanprover.zulipchat.com](https://leanprover.zulipchat.com/#narrow/channel/113488-general/topic/con-agua.2C.20an.20x86.20assembly.20port.20of.20con-leche/with/634779855))
- **Resolution uses Claude Fable 5.1 to formalize Hironaka's resolution of singularities.** The library, written in Lean 4 over Mathlib, proves Hironaka's main theorems in characteristic zero and their refinements by Kollár, Włodarczyk and Bierstone–Milman, for algebraic schemes and analytic manifolds and spaces. Chris Elliott at Resolution directed and audited the automated formalization process, and the code is licensed under Apache License 2.0. ([resolutionorg/hironaka](https://github.com/resolutionorg/hironaka), [resolutionorg.github.io](https://resolutionorg.github.io/hironaka/), [reservoir.lean-lang.org](https://reservoir.lean-lang.org/@resolutionorg/hironaka))
- **Miles Cranmer's AI agents model Julia code in Lean and find bugs.** Lean definitions mirror Julia functions line by line, and each property ends proven, or refuted with a concrete counterexample and a pure-Julia reproducer. In Julia Base and several standard libraries, 400 of 910 properties were refuted and 75 issues filed on JuliaLang/julia; DynamicExpressions.jl, the expression-tree package behind PySR, merged 38 Lean-derived fixes. ([MilesCranmer/julia-in-lean](https://github.com/MilesCranmer/julia-in-lean))

## Verification in practice

- **AssureCode uses Lean for structured justification of AI-generated code.** Logan Murphy and coauthors describe AssureCode, which autoformalizes developer intent into Lean specifications for human approval, then decomposes claims via Lean templates, with Lean checking an agent's decomposition-soundness proofs. On HumanEval, LiveCodeBench and MBPP samples with four LLMs, a single run recovered most of an iterative LLM baseline's concerns and surfaced additional ones. ([arXiv:2610.29758](https://arxiv.org/abs/2610.29758), [paperswithlean.com](https://paperswithlean.com/paper/2610.29758.html))
- **Thomas Coratger announces EthLib, a Lean 4 library for Ethereum.** The library, hosted at github.com/ethereum/EthLib, launched with the goal of bringing Ethereum's primitives, specifications and theorems into one place, building a shared foundation for formally specifying and proving things about Ethereum. ([@tcoratger on X](https://x.com/tcoratger/status/2114395664687771936))
- **Katzenpost's Lean library Cryptlib implements the Sphinx cryptographic packet format.** Cryptlib's Sphinx packets are binary compatible with the Katzenpost mix network's Go implementation, including with a post-quantum/classical hybrid key encapsulation method (X25519 and ML-KEM-768) per hop. The AGPLv3-licensed library is for modeling protocols and proving their properties; each kind of primitive has a Lean structure with proposition fields that every instance must satisfy. ([katzenpost/cryptlib](https://github.com/katzenpost/cryptlib), [cryptlib.io](https://cryptlib.io/), [reservoir.lean-lang.org](https://reservoir.lean-lang.org/@katzenpost/cryptlib))
- **GitHub user joehattori uses Aeneas and Lean to verify core crosvm components.** In crosvm-verif, Charon and Aeneas extract Rust code and generate Lean, and `make verify` checks the Lean translation and its specifications. The package is also listed on Reservoir, the package registry for Lake, Lean's build system and package manager. ([joehattori/crosvm-verif](https://github.com/joehattori/crosvm-verif), [reservoir.lean-lang.org](https://reservoir.lean-lang.org/@joehattori/crosvm-verif))

## Verification in practice

- **Jonathan Protzenko uses Aeneas to verify bounds safety in jxl-rs.** Jonathan Protzenko's case study uses Aeneas, a toolchain for verifying Rust programs through a functional translation to Lean, on jxl-rs, a Rust rewrite of the jpeg-xl codec. The proof shows an unchecked array access always stays within bounds and showcases recent Aeneas features, including official grind support and loop combinators. ([jonathan.protzenko.fr](https://jonathan.protzenko.fr/2026/05/05/jxl-rs.html))

## Lean core and ecosystem

- **Sebastian Graf merges experimental mvcgen' tactic into the Lean toolchain.** The pull request adds mvcgen', reimplemented from the ground up on the new SymM-based framework for efficient symbolic evaluation. It will soon replace mvcgen and can outperform it by a factor of more than 100 on some synthetic benchmarks. Join point sharing and introduction of local specs are not yet supported. ([lean4#13644](https://github.com/leanprover/lean4/pull/13644))
- **Leo de Moura merges a series of grind fixes into Lean.** The merged pull requests fix grind's AC invariants, a congruence-table panic, cast internalization order and missing proof hints. A new ringMaxDegree option (default 1024) bounds polynomial degree in the ring solver, and derived tactics such as lia, linarith and ring now fail quickly on out-of-scope problems. ([lean4#13593](https://github.com/leanprover/lean4/pull/13593), [lean4#13585](https://github.com/leanprover/lean4/pull/13585), [lean4#13590](https://github.com/leanprover/lean4/pull/13590), [lean4#13624](https://github.com/leanprover/lean4/pull/13624), [lean4#13625](https://github.com/leanprover/lean4/pull/13625), [lean4#13623](https://github.com/leanprover/lean4/pull/13623), [lean4#13614](https://github.com/leanprover/lean4/pull/13614), [lean4#13622](https://github.com/leanprover/lean4/pull/13622))
- **Leo de Moura fixes a panic and an assertion failure in Sym.simp.** One merged Lean 4 pull request fixes a Sym.simp panic triggered when match reduction exposed kernel projection terms, for example in a do block with a for loop over tuple state. Another removes an incorrect assertion that failed on have-expressions whose binder type depends on an earlier binder. ([lean4#13635](https://github.com/leanprover/lean4/pull/13635), [lean4#13611](https://github.com/leanprover/lean4/pull/13611), [lean4#13612](https://github.com/leanprover/lean4/pull/13612))
- **Mac Malone extends Lean-to-Python module initialization in Nerodia.** Mac Malone's merged pull request lets a Lean-written initializer add a constant to the Python module, adds Lean-side argument validation, and adds a Lean-to-Python-to-Lean test. A second merged change splits the global Python state (g_py_main) from the per-use GIL context (py_context). ([nerodia#3](https://github.com/leanprover/nerodia/pull/3), [nerodia#4](https://github.com/leanprover/nerodia/pull/4))
- **Wojciech Nawrocki adds a VSCode extension to lean-workbench.** A pull request by Wojciech Nawrocki, merged on 2026-05-05, adds a VSCode extension to integrate it with the workbench in the leanprover/lean-workbench repository. The change also adds a launch target and server endpoint to debug the extension. ([lean-workbench#9](https://github.com/leanprover/lean-workbench/pull/9))
- **Wojciech Różowski moves Batteries linters into Lean core and extends lake lint.** Wojciech Różowski upstreamed the dupNamespace and unnecessarySeqFocus linters from Batteries to core Lean as "clippy" linters, which are disabled by default and run with lake lint --clippy. lake lint --builtin-lint now also supports text linters, and a new script reports deprecated modules, options and syntax usage. ([lean4#13513](https://github.com/leanprover/lean4/pull/13513), [lean4#13538](https://github.com/leanprover/lean4/pull/13538), [lean4#13540](https://github.com/leanprover/lean4/pull/13540), [lean4#13586](https://github.com/leanprover/lean4/pull/13586))

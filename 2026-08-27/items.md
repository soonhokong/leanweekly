## Headlines

- **Lean FRO publishes postmortem of kernel soundness bug hunt with OpenAI models.** Daniel Selsam used OpenAI internal models to find soundness issues in the official Lean kernel and runtime from July 30 to August 20, and Lean v4.33.1, released August 21, fixes all of them. Starting with Lean v4.35.0, lake check will export and recheck projects using lean4checker. ([leodemoura.github.io](https://leodemoura.github.io/blog/2026-8-24-postmortem-for-the-kernel-soundness-bug-hunt))
- **Lean FRO publishes six-month roadmap for September 2026 to February 2027.** The roadmap covers lake check commands for external kernel checking, a code formatter, Nerodia (a Lean/Python FFI inspired by PyO3), and faster typeclass inference. It also covers the FRO's AI projects Tau Ceti, Hex, and Palomar, and defers investment in debugger infrastructure. ([lean-lang.org](https://lean-lang.org/fro/roadmap/y4-1/))
- **Lean v4.33.1 patches kernel soundness bugs, v4.34.0-rc2 also published.** Lean v4.33.1 is a patch release with runtime and kernel fixes, including soundness issues reported by Daniel Selsam (OpenAI) using OpenAI's internal models, and all users of v4.33.0 or earlier are encouraged to upgrade. Release candidate 2 for v4.34.0 was published the same day. ([v4.33.1 release notes](https://lean-lang.org/doc/reference/stable/releases/v4.33.1/), [lean4 v4.33.1](https://github.com/leanprover/lean4/releases/tag/v4.33.1), [lean4 v4.34.0-rc2](https://github.com/leanprover/lean4/releases/tag/v4.34.0-rc2), [v4.34.0 release notes](https://lean-lang.org/doc/reference/latest/releases/v4.34.0/))
- **Sebastian Ullrich fixes reference count overflow that could enable a proof of False.** A merged Lean 4 pull request freezes objects whose 32-bit reference count overflows, preventing a use-after-free in the official kernel. The new logic is validated with a transliteration of its core to Lean followed by correctness proofs in a test file. Daniel Selsam (OpenAI) reported the issue using internal models. ([lean4#14838](https://github.com/leanprover/lean4/pull/14838))
- **SAIR Foundation and Lean FRO announce the Lean Kernel Challenge competition.** The competition asks participants to improve the performance of verified computation in the Lean 4 kernel (the trusted component that checks every proof accepted by Lean) with optimized implementations and machine-checked proofs of correctness. Stage 1 pre-registration is open, with the official launch on September 15, 2026. ([@Leonard41111588 on X](https://x.com/Leonard41111588/status/2092297497293066592), [LinkedIn post](https://www.linkedin.com/feed/update/urn:li:activity:7498062411179098112/))

## AI and formalization

- **Lean FRO and ICARM open Palomar, a registry of Lean-verified mathematics.** Palomar, a public, searchable registry of machine-checked Lean formalizations incubated by the Lean FRO and ICARM, is now open for submissions, Terence Tao announced. Submitted repository snapshots are checked mechanically with the Lean tool Comparator and by a large language model, though Palomar is not a peer-reviewed journal. ([terrytao.wordpress.com](https://terrytao.wordpress.com/2026/08/18/palomar-a-registry-of-lean-verified-mathematics/), [LinkedIn post](https://www.linkedin.com/feed/update/urn:li:activity:7498115329475166208/))
- **Vero benchmark tests AI agents on verified Lean 4 software repositories.** Researchers including Kaiyu Yang, Soonho Kong, Jingxuan He, and Dawn Song introduce Vero, a benchmark of 43 multi-module instances sourced from real-world repositories, each a multi-module Lean 4 repository with predetermined API interfaces. The strongest agent fully solves only 27 of 43 instances. ([arXiv:2608.13522](https://arxiv.org/abs/2608.13522))
- **Scott Armstrong says Lean formalization became essential to his research in 2026.** Scott Armstrong wrote on X that in March, Lean formalization was not possible for his papers, and by August it had become essential and increased the efficiency of his workflow dramatically. Scott Armstrong says the papers are getting written informally and finished much faster because of the Lean formalization. ([@scottnarmstrong on X](https://x.com/scottnarmstrong/status/2091098230855491978))
- **Vasily Ilin runs a collaborative Lean 4 formalization of Mazur's torsion theorem.** The Vilin97/MazurTheorem repository targets the classification of rational torsion on elliptic curves, using Mazur's degree-one formal-immersion argument at the auxiliary prime 5. The project reports an integrated score of 17.2% on its 48-node, 1,000-point theorem DAG, and it accepts claims only on contracts marked open or research_open. ([Vilin97/MazurTheorem](https://github.com/Vilin97/MazurTheorem))

## Verification in practice

- **Paul Butcher builds a complete production TodoMVC webapp in Lean 4.** The repository adds passwordless sign-in, SQL migrations, OpenTelemetry traces and logs, an MCP endpoint, and deployment to AWS Lambda, built on Paul Butcher's own Lean libraries. Markup is typed and formally verified (a `<div>` inside a `<p>` is a type error), and lean-json is proved correct against the grammar of RFC 8259. ([paulbutcher/lean-todomvc-max](https://github.com/paulbutcher/lean-todomvc-max))

## Lean core and ecosystem

- **Lean 4 redefines Decidable as a Bool paired with a proof.** A pull request by Robin Arnez, merged on 2026-08-20, changes `Decidable p` to a structure containing a `Bool` and a proof of either `p` or `¬p`, giving more definitional equalities and letting the `decide` tactic stop carrying proofs. The breaking change was possible now that the new compiler is enabled. ([lean4#8309](https://github.com/leanprover/lean4/pull/8309))
- **Lean adds leanchecker-paranoid and lake challenge; Joachim Breitner releases inductive models.** Sebastian Ullrich merged leanchecker-paranoid, a variant of leanchecker built with allocator hardening, and lake challenge, a frontend to comparator that simplifies its setup. Joachim Breitner's lean-inductive-models performs translation validation of user-defined Lean inductives into an extensional type system with a small hard-coded inductive basis. ([lean4#14885](https://github.com/leanprover/lean4/pull/14885), [lean4#14884](https://github.com/leanprover/lean4/pull/14884), [nomeata/lean-inductive-models](https://github.com/nomeata/lean-inductive-models), [arena.lean-lang.org](https://arena.lean-lang.org/))
- **Renaissance Philanthropy runs the CSLib Initiative to support CSLib's growth.** The CSLib Initiative, a program of Renaissance Philanthropy, supports the growth of the CSLib open-source project (a focused effort on formalizing computer science in Lean) in the same way that the Mathlib Initiative supports Mathlib. Its site lists a team, a Strategic Advisory Board, and a roadmap of operational goals guiding its funding. ([cslib.io](https://www.cslib.io/initiative/))
- **Sebastian Graf moves VERINA contracts onto programs and names verification-condition variables.** Two merged Lean pull requests by Sebastian Graf state each VERINA program's requires, ensures and loop invariants on the definition itself, for all 27 programs. A second pull request names a verification condition's variables after the program (acc, x instead of b✝), so proofs no longer need rename_i. ([lean4#14759](https://github.com/leanprover/lean4/pull/14759), [lean4#14590](https://github.com/leanprover/lean4/pull/14590))
- **Lake now fetches dependencies as treeless partial Git clones.** A merged pull request by Mac Malone makes Lake fetch dependencies as treeless partial Git clones of a single revision, minimizing the amount of data downloaded. One caveat: Git operations inside a dependency, such as a git blame triggered by a VSCode extension, can cause lazy fetches. ([lean4#14782](https://github.com/leanprover/lean4/pull/14782))
- **Lean adds strong coinduction principles and a monotonicity_by clause for predicates.** Wojciech Różowski merged a Lean pull request that generates strong_coinduct for coinductive_fixpoint predicates, strengthening coinduct, plus strong_induct for inductive_fixpoint ones. A second merged pull request adds a monotonicity_by clause so users can prove monotonicity of the underlying fixpoint functor with an explicit tactic block when automatic proof search fails. ([lean4#14855](https://github.com/leanprover/lean4/pull/14855), [lean4#14861](https://github.com/leanprover/lean4/pull/14861))

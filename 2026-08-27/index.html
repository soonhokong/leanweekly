Lean core·Aug 24

Lean FRO publishes postmortem of kernel soundness bug hunt with OpenAI models

Daniel Selsam used OpenAI internal models to find soundness issues in the official Lean kernel and runtime from July 30 to August 20, and Lean v4.33.1, released August 21, fixes all of them. Starting with Lean v4.35.0, lake check will export and recheck projects using lean4checker.

Lean core·Aug 27

Lean FRO publishes six-month roadmap for September 2026 to February 2027

The roadmap covers lake check commands for external kernel checking, a code formatter, Nerodia (a Lean/Python FFI inspired by PyO3), and faster typeclass inference. It also covers the FRO's AI projects Tau Ceti, Hex, and Palomar, and defers investment in debugger infrastructure.

Lean core·Aug 20

Sebastian Ullrich fixes reference count overflow that could enable a proof of False

A merged Lean 4 pull request freezes objects whose 32-bit reference count overflows, preventing a use-after-free in the official kernel. The new logic is validated with a transliteration of its core to Lean followed by correctness proofs in a test file. Daniel Selsam (OpenAI) reported the issue using internal models.

⊢Checked against: lean4#14838

Lean FRO and ICARM open Palomar, a registry of Lean-verified mathematics

Palomar, a public, searchable registry of machine-checked Lean formalizations incubated by the Lean FRO and ICARM, is now open for submissions, Terence Tao announced. Submitted repository snapshots are checked mechanically with the Lean tool Comparator and by a large language model, though Palomar is not a peer-reviewed journal.

AI and formalization·Aug 27

Vasily Ilin runs a collaborative Lean 4 formalization of Mazur's torsion theorem

The Vilin97/MazurTheorem repository targets the classification of rational torsion on elliptic curves, using Mazur's degree-one formal-immersion argument at the auxiliary prime 5. The project reports an integrated score of 17.2% on its 48-node, 1,000-point theorem DAG, and it accepts claims only on contracts marked open or research_open.

Lean core·Aug 20

Lean 4 redefines Decidable as a Bool paired with a proof

A pull request by Robin Arnez, merged on 2026-08-20, changes Decidable p to a structure containing a Bool and a proof of either p or ¬p, giving more definitional equalities and letting the decide tactic stop carrying proofs. The breaking change was possible now that the new compiler is enabled.

⊢Checked against: lean4#8309

Lean core·Aug 17

Lake now fetches dependencies as treeless partial Git clones

A merged pull request by Mac Malone makes Lake fetch dependencies as treeless partial Git clones of a single revision, minimizing the amount of data downloaded. One caveat: Git operations inside a dependency, such as a git blame triggered by a VSCode extension, can cause lazy fetches.

⊢Checked against: lean4#14782

Lean core·Aug 25

Lean adds strong coinduction principles and a monotonicity_by clause for predicates

Wojciech Różowski merged a Lean pull request that generates strong_coinduct for coinductive_fixpoint predicates, strengthening coinduct, plus strong_induct for inductive_fixpoint ones. A second merged pull request adds a monotonicity_by clause so users can prove monotonicity of the underlying fixpoint functor with an explicit tactic block when automatic proof search fails.

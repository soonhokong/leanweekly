## Headlines

- **Claude raises Riemann zeta zero bound to 67.2%, formalized in Lean.** An unreleased research version of Claude increased the lower bound for the fraction of Riemann zeta zeros satisfying the Riemann hypothesis from 41.6% to 67.2%. Claude and Eric Easley produced a Lean formalization that passes comparator, the validation tool originally developed by Lean FRO with feedback from the AIMO team. ([anthropic.com](https://www.anthropic.com/research/riemann-zeta), [anthropics/zeta-23-lean](https://github.com/anthropics/zeta-23-lean), [leanprover/comparator](https://github.com/leanprover/comparator))
- **Lean 4.33.0 released with editor, tactic, Float, and kernel changes.** Lean 4.33.0, published 2026-08-10, makes the editor more responsive, lets try? propose proofs on its own, improves the lia and grind tactics, and stops Float from being an opaque type. It also fixes kernel soundness bugs and enables backward.isDefEq.respectTransparency.types by default, the change most likely to need attention when porting. ([v4.33.0 release notes](https://lean-lang.org/doc/reference/latest/releases/v4.33.0/), [lean4 v4.33.0](https://github.com/leanprover/lean4/releases/tag/v4.33.0))
- **Kim Morrison releases an integer polynomial factorization library for Lean.** The library, part of Hex, the computer algebra library for Lean, includes tactics for factorizing and irreducibility and implements van Hoeij's knapsack method, which according to Kim Morrison has never previously been formally verified. It builds on hex-lll, whose theory package proves that both lattice reducers satisfy their reducedness and lattice-preservation contracts. ([LinkedIn post](https://www.linkedin.com/posts/kim-morrison-219962b_lean-mathlib-activity-7492744920349192193-G3Me), [leanprover/hex-lll](https://github.com/leanprover/hex-lll))

## Verification in practice

- **Predictable Machines builds Predictable Code on Lean 4, open-sources two libraries.** Predictable Code uses Lean 4 formal verification to prove that AI-generated code matches specifications, and is currently in private beta. Predictable Machines also open-sourced lean4-json-schema, which derives JSON Schemas from types and proves at compile time that serialization always validates, and lean4-tree-sitter, typed bindings for tree-sitter. ([predictablemachines.com](https://predictablemachines.com/blog/why-we-chose-lean-for-predictable-code/), [code.predictablemachines.com](https://code.predictablemachines.com/), [predictablemachines.com](https://predictablemachines.com/blog/announcing-lean4-json-schema/), [predictablemachines.com](https://predictablemachines.com/blog/announcing-lean4-tree-sitter/))

## Lean core and ecosystem

- **Guide explains how to validate and report Lean kernel soundness bugs.** A "Kernel bug hunt" document explains what counts as a Lean kernel soundness bug and how to validate a candidate before reporting it, using lake check, comparator (the validation tool) or its web interface. Starting with Lean v4.35.0, the distribution bundles four additional kernels, two of them formally verified. ([hackmd.io](https://hackmd.io/@f6l0w8kXTciyFFqVRXVh5A/rJActgtIMx))
- **Sebastian Graf extends Lean's def contracts and vcgen loop verification.** Merged pull requests let `repeat` and `while` loops state the invariant and termination measure that `vcgen` needs, so a loop inside a `def` with a contract verifies without manual proof steps. Other changes allow match alternatives in `ensures` clauses, invariants on destructuring `for` loops, and type ascriptions on contract binders. ([lean4#14703](https://github.com/leanprover/lean4/pull/14703), [lean4#14701](https://github.com/leanprover/lean4/pull/14701), [lean4#14682](https://github.com/leanprover/lean4/pull/14682), [lean4#14686](https://github.com/leanprover/lean4/pull/14686), [lean4#14669](https://github.com/leanprover/lean4/pull/14669), [lean4#14685](https://github.com/leanprover/lean4/pull/14685))
- **Paul Reichert fixes instance search seeing through type synonyms in Lean.** Paul Reichert's merged PR ensures that, during instance search, metavariables for instance-implicit arguments are only assigned values of the expected type, fixing an issue Sebastien Gouezel hit while formalizing Riemannian metrics in Mathlib. A preparatory PR brought a clear performance improvement with no Mathlib breakage observed. Affected Mathlib declarations were fixed with a backward compatibility option. ([lean4#14624](https://github.com/leanprover/lean4/pull/14624), [lean4#14583](https://github.com/leanprover/lean4/pull/14583), [lean4#9077](https://github.com/leanprover/lean4/issues/9077))
- **Lean releases Nerodia, a library for writing Python modules in Lean.** Nerodia, a Lean/Python FFI library inspired by PyO3, uses Lake, Lean's build system, to build native Python modules in pure Lean and generates type stubs automatically. It is a work-in-progress with a very limited API, released primarily as a proof-of-concept and to obtain feedback on its design and build process. ([leanprover/nerodia](https://github.com/leanprover/nerodia))
- **Leo de Moura adds a lift_lets tactic for Lean's sym => mode.** The merged pull request moves let/have declarations of the goal toward the root as far as dependencies allow. The new Sym.liftLets implementation is near-linear in the DAG size of the input term, running 680x faster than Meta.liftLets on a chain of 4000 lets and taking 85 ms for 32000. ([lean4#14768](https://github.com/leanprover/lean4/pull/14768))
- **Mac Malone merges Lake remote cache fixes, tests, and a --package option.** Lake now demotes cache failures during a build to trace-level messages, so builds run with --wfail or --iofail do not fail solely due to the cache, and lake cache get gains --package to fetch outputs for a specific workspace package. A new test mocks remote cache transfers with a mock Python HTTP server. ([lean4#14720](https://github.com/leanprover/lean4/pull/14720), [lean4#14724](https://github.com/leanprover/lean4/pull/14724), [lean4#14700](https://github.com/leanprover/lean4/pull/14700))

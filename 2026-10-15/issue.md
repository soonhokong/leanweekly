## Headlines

- **Lean 4.35.0 ships vcgen, lake check, and bundled independent kernels.** Lean 4.35.0, published on 2026-10-12, adds vcgen, a faster and more general successor of mvcgen, plus lake check and lake comparator, which check a project with Lean's kernel and optionally several independent kernels now included in the toolchain. ([v4.35.0 release notes](https://lean-lang.org/doc/reference/latest/releases/v4.35.0/), [lean4 v4.35.0](https://github.com/leanprover/lean4/releases/tag/v4.35.0))
- **OpenAI publishes 719 model-produced math manuscripts, about 42% Lean-formalized.** OpenAI's openai/math repository holds manuscripts and proof artifacts produced by an internal OpenAI model, organized into 372 families, with 300 of 719 top-line results formalized in Lean. An October 7, 2026 update withdrew three manuscripts after a sign error and revised 14 others. ([openai/math](https://github.com/openai/math), [openai/math](https://github.com/openai/math/blob/main/history.md))
- **Four authors formalize the Hamilton-Perelman proof of the Poincaré conjecture in Lean.** Ziyang Qin, Yuan Liao, Ayush Khaitan, and Bennett Chow formalize the smooth three-dimensional Poincaré conjecture via Ricci flow with surgery and finite-time extinction. Together with the Moise smoothing theorem, the result yields the topological three-dimensional Poincaré conjecture. ([arXiv:2609.33842](https://arxiv.org/abs/2609.33842))
- **Renaissance Philanthropy and XTX Markets announce $17.1 million in AI for Math grants.** The AI for Math Fund selected 22 applications representing 30 organizations from more than 470 submissions, bringing its total commitments to $35.1 million. Winners include TorchLean, a Lean-native framework for verified machine learning, and a project turning a Lean 4 visual proofwriting prototype into open-source infrastructure for reading AI-generated proofs. ([renaissancephilanthropy.org](https://www.renaissancephilanthropy.org/insights/renaissance-philanthropy-and-xtx-markets-announce-further-171-million-to-accelerate-mathematical-progress))
- **AI proof-search agent resolves nine open Erdős problems, verified in Lean.** A paper in Science by George Tsoukalas, Swarat Chaudhuri and coauthors describes an agent for formal proof search that autonomously resolved nine of 353 open Erdős problems and proved 44 of 492 On-Line Encyclopedia of Integer Sequences conjectures. A basic agent alternating LLM-based generation with Lean-based verification replicated the Erdős successes. ([science.org](https://www.science.org/doi/10.1126/science.aej2213))

## AI and formalization

- **Machine-checked Lean 4 proof of the general Courtade–Kumar inequality released.** A repository by @dpwoodru contains a complete, machine-checked Lean 4 proof of the general Courtade–Kumar inequality (the most informative Boolean function conjecture), formalizing the paper by Z. Chen, A. Gohari, A. Javanmard, H. Lin, V. Mirrokni, C. Nair and D. P. Woodruff. The whole proof spans 45,500 modules. ([dpwoodru/general-courtade-kumar-lean](https://github.com/dpwoodru/general-courtade-kumar-lean))
- **Scott Armstrong publishes skill files for LLM-driven Lean autoformalization.** Scott Armstrong writes that autoformalization of research-level mathematics has become easy, citing a Lean formalization of a 145-page paper with Vicol in about 36 hours (270k lines of code), and makes the agent skill files public. A separate Xena post weighs mathematicians' reactions to AI, noting "You cannot fool Lean." ([scottnarmstrong.com](https://www.scottnarmstrong.com/2026/10/autoformalization-is-now-very-easy/), [xenaproject.wordpress.com](https://xenaproject.wordpress.com/2026/10/01/to-grieve-or-not-to-grieve/))
- **Google's Gemini 4 Argon writes a Lean-verified quantum arcsin implementation.** Google's launch post for Gemini 4 Argon (dated 2026-10-13) reports an arcsin implementation, a building block in recent quantum simulation algorithms, written by Argon and formally verified in Lean. It cuts spacetime cost by more than 100x compared to a published quantum CORDIC baseline. ([blog.google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-argon/))

## Verification in practice

- **Trail of Bits proves Miden core library arithmetic correct with AI-generated Lean proofs.** During an audit of the Miden VM, a zero-knowledge VM with its own assembly language, Trail of Bits had agents build a Lean model of the VM executor, producing 95 correctness proofs covering all binary arithmetic components of the core library. The work identified two subtle bugs that the existing unit test suite did not catch. ([blog.trailofbits.com](https://blog.trailofbits.com/2026/09/18/auditing-in-the-age-of-good-enough-ai/))
- **Emina Torlak presents SymCert, a Lean framework for verified Cedar policy analyses.** SymCert, implemented in Lean, builds verified SMT-based analyses of Cedar policies, an open-source authorization language. In the FMCAD 2026 paper, five analyses used in a Cedar analysis service at Amazon Web Services were modeled and proved in one work day, and three extensions for new Cedar features took 4 to 8 days each. ([cdn.amazon.science](https://cdn.amazon.science/9f/c9/5d18658a41c48628b686493aa327/scipub-approval152134-46496997-symcert-verifying-smtbased-policy-analyses.pdf))
- **Flapjack ports the verified Pancake compiler from HOL4 to Lean.** Flapjack is bringing the Pancake compiler, originally verified in HOL4, and its proofs to Lean, with a path compiling a fragment of Pancake to RISC-V where all stages except parsing and AST conversion have a correctness theorem. A MIPS32 backend targets the Ziren zkVM, but its output has been run only on Ziren's Lean model. ([flapjack-lang.dev](https://flapjack-lang.dev/))

## Lean core and ecosystem

- **Lean reference manual documents vcgen, the successor of mvcgen in Lean 4.35.** A pull request by Sebastian Graf documents the vcgen tactic and its Std.WP framework, adds the tutorial "Verifying Imperative Programs Using vcgen", and moves the mvcgen chapter and tutorial to their own files. The Kraken project already uses vcgen to prove that FFmpeg's FMA3 dot-product loop, over two arrays that may alias, terminates without faulting. ([reference-manual#927](https://github.com/leanprover/reference-manual/pull/927), [zrlk/kraken](https://github.com/zrlk/kraken/blob/vcgen/Kraken/X64/Examples/FfScalarproductFloatFma3.lean))
- **Sebastian Ullrich makes Lean's type class resolution cache persist across commands.** Two merged pull requests by Sebastian Ullrich keep type class resolution results for later commands and let queries differing only in free variables share a cache entry. Building Mathlib takes about 4% fewer instructions and 8% less wall-clock time, and spends about 16% less time in type class resolution. ([lean4#14369](https://github.com/leanprover/lean4/pull/14369), [lean4#14316](https://github.com/leanprover/lean4/pull/14316))
- **Joachim Breitner and Lean FRO describe the proof behind con-leche checker.** con-leche, a checker for Lean 4, comes with a proof in Lean that every environment it accepts has a model in set theory, so no accepted environment holds a proof of False. A new document gives a pen-and-paper account of that argument on a simplified fragment of the checker. ([leanprover.github.io](https://leanprover.github.io/con-leche/con-leche-proof-idea.html))
- **Sebastian Ullrich removes Lean's 255-object-field limit per constructor.** A merged pull request by Sebastian Ullrich removes the limit of 255 object fields per constructor, and thus per structure. When a constructor has more, the compiler keeps the first 254 in the constructor object and stores the rest in a chain of spill objects, with one pointer followed per spill object on access. ([lean4#15516](https://github.com/leanprover/lean4/pull/15516))
- **Julia Markus Himmel reworks order instances across Lean core types.** Julia Markus Himmel redefined the order on String as the lexicographic order of its UTF-8 encoding, made Min Float follow the IEEE-754-2019 minimum operation, and added missing order instances for BitVec, List, Array, Vector and ByteArray. Sofia Rodrigues fixed leaks and refactored the libuv bindings. ([lean4#15581](https://github.com/leanprover/lean4/pull/15581), [lean4#15257](https://github.com/leanprover/lean4/pull/15257), [lean4#15274](https://github.com/leanprover/lean4/pull/15274), [lean4#15304](https://github.com/leanprover/lean4/pull/15304), [lean4#15329](https://github.com/leanprover/lean4/pull/15329), [lean4#15175](https://github.com/leanprover/lean4/pull/15175), [lean4#15545](https://github.com/leanprover/lean4/pull/15545))
- **Lean core gains an HTML type, renderer, and HTML-like syntax.** Wojciech Nawrocki merged pull requests adding Lean.Data.Html, a type of HTML forests aimed at authoring HTML, with a renderer to String, plus HTML-like syntax and an elaborator into that type. Separately, Emilio Jesús Gallego Arias added optional VIR support and a small Lean-to-JavaScript client example on Lean 4.35 to Verso Blueprint. ([lean4#14935](https://github.com/leanprover/lean4/pull/14935), [lean4#15002](https://github.com/leanprover/lean4/pull/15002), [verso-blueprint#491](https://github.com/leanprover/verso-blueprint/pull/491))
- **Leo de Moura adds option to run grind on Sym.simp normalizer.** A merged Lean pull request adds backward.grind.normalizer, which switches grind to the Sym.simp-based normalizer when set to false (the default behavior is unchanged). Related changes add grind_norm, a debugging tactic whose check mode runs both normalizers and fails when results differ, and fix negation-pushing rewrites that had been dead code since #9271. ([lean4#15464](https://github.com/leanprover/lean4/pull/15464), [lean4#15375](https://github.com/leanprover/lean4/pull/15375), [lean4#15378](https://github.com/leanprover/lean4/pull/15378))
- **Sebastian Ullrich merges two fixes to how Lean modules export theorems.** In Lean, an asynchronously elaborated theorem's exported info in a `module` is now available as soon as its signature is, instead of after its proof is elaborated. A second change stops modules from exporting constants such as `foo.eq_1` realized only inside a proof, so such proofs no longer trigger downstream rebuilds. ([lean4#15559](https://github.com/leanprover/lean4/pull/15559), [lean4#15563](https://github.com/leanprover/lean4/pull/15563))
- **Lean Workbench adds basic static Verso publications.** A merged pull request by Jason Reed adds a Publish button to the project summary when a workbench-publication.json file configures Verso builds. Clicking it runs a Verso build and serves the result on a route extending the project URL. A follow-up makes publications create temporary directories in roughly the same way as tracked commands. ([lean-workbench#139](https://github.com/leanprover/lean-workbench/pull/139), [lean-workbench#149](https://github.com/leanprover/lean-workbench/pull/149))
- **Kim Morrison proposes supply-chain audits for Mathlib dependency updates.** A Mathlib pull request by Kim Morrison adds a supply-chain audit step to the hourly update_dependencies.yml workflow, posting diffs, high-risk files touched and suspicious added lines for each changed dependency. The diffs come from paranoid-lake-update, which uses bare clones and git only, so nothing from upstream is executed. ([mathlib4#43911](https://github.com/leanprover-community/mathlib4/pull/43911))

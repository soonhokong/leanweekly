Lean core·May 5

Sebastian Graf brings Sym-based mvcgen' to parity with mvcgen

A merged Lean pull request by Sebastian Graf gives the Sym-based mvcgen' feature parity with mvcgen, except +jp (join-point handling), at a cost of about 10% vcgen slowdown for cleaner user-visible VCs. A separate change adds whileM, which makes repeat/while loops verifiable with mvcgen.

⊢Checked against: lean4#13578·lean4#13209·lean4#13672·lean4#13582

Lean core·Apr 30

Joachim Breitner's experimental nanobruijn kernel type-checks all of Mathlib

nanobruijn, an experimental Lean 4 type checker in Rust forked from nanoda_lib, keeps expressions as pure de Bruijn indices with shift-homomorphic caching, and type-checks all of Mathlib (670k declarations) with 0 errors and 0 timeouts. The code changes were written by Claude (Anthropic), directed by Joachim Breitner.

⊢Checked against: nomeata/nanobruijn

Lean core·Apr 29

Leo de Moura merges grind diagnostics, solver fixes, and a ring-degree limit

The new grind.ematch.diagnostics option tracks how E-matching theorem instances depend on each other, and a ringMaxDegree option (default 1024) bounds polynomial degree in the grind ring solver. Other merged pull requests fix beta reduction to respect the generation threshold, fix a kernel error for Nat casts to non-Int types, and extend the homomorphism demo.

⊢Checked against: lean4#13558·lean4#13585·lean4#13560·lean4#13453·+2 more

Lean core·Apr 22

Lake gains builtin environment linting through new lake lint flags

A pull request by Wojciech Różowski, merged on 2026-04-22, adds builtin environment linting support to Lake, accessible via lake lint flags such as --builtin-lint and --clippy. It also introduces two builtin linters upstreamed from Mathlib (defLemma and checkUnivs) and a builtinLint package configuration option.

⊢Checked against: lean4#13431

Lean core·Apr 9

Lean releases Nerodia, a work-in-progress library for writing Python modules in Lean

Nerodia is a library for Lean/Python FFI inspired by PyO3 that uses Lake, Lean's build system, and generates type stubs for editors. It has a very limited API and is released primarily as a proof-of-concept and to obtain feedback on its design and build process.

⊢Checked against: leanprover/nerodia

Lean core·Apr 9

Design note proposes a two-tier design for grind scalability

A HackMD note proposes to "separate the cheap default from the expensive exploration": a default grind mode that is cheap, fast and fails quickly, plus explicit named tactics such as nonlinear_ineqs and fin_cases that users, grind?, or AI invoke to produce replayable scripts.

⊢Checked against: hackmd.io

Lean core·Apr 9

Verso Blueprint publishes FLT and Sphere Packing blueprints as reference ports

The leanprover/verso-blueprint package, for writing Blueprint documents in Verso, now publishes Verso ports of the FLT and Sphere Packing blueprints, while Noperthedron and Carleson sit outside the catalog on the retired 4.34 line. Emilio Jesús Gallego Arias's porting harness has a human use Codex CLI to carry out the porting work.

⊢Checked against: leanprover/verso-blueprint·ejgallego.github.io·ejgallego.github.io·ejgallego.github.io·+2 more

Lean core·Apr 2

leanprover-community releases a tool for offline Lean 4 teaching bundles

The bundle tool creates self-contained Lean 4 bundles for teaching: students download a zip, unpack it, double-click "Start_Lean", and get a working editor with no installation, no network access, and no command line needed. Each bundle ships VSCodium with the lean4 extension and only the oleans the project needs.

⊢Checked against: leanprover-community/bundle

Lean core·Mar 27

Lean 4.29.0 released with a new extensible do elaborator

The release changes reducibility handling: isDefEq no longer bumps transparency when comparing implicit arguments, and a new @[implicit_reducible] attribute and a backward-compatibility option ease migration. It also adds grind support for higher-order Miller patterns, mvcgen support for specifications in the local context, and faster startup.

⊢Checked against: v4.29.0 release notes·lean4 v4.29.0

A merged pull request by Henrik Böving ports the C emission pass from IR to LCNF. The PR describes this as the last step of the IR/LCNF conversion, enabling end-to-end code generation through the new compilation infrastructure.

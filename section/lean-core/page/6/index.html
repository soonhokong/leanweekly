Lean core·Feb 18

Lean v4.29.0-rc1 changes how isDefEq handles transparency on implicit arguments

Leo de Moura's lean#12179, merged on 2026-02-16, stops isDefEq from raising transparency to .default for implicit arguments, a behavior that caused scalability problems in Mathlib. Kim Morrison advises downstream projects not to move to v4.29.0-rc1 yet, and a later PR documents the design rationale behind the transparency hierarchy.

⊢Checked against: leanprover.zulipchat.com·lean4#12179·lean4#12561

Lean core·Feb 17

Lean v4.28.0 released with a symbolic simulation framework and grind extensions

Lean v4.28.0 adds a lightweight symbolic simulation framework that integrates with grind and enables verification condition generators, plus user-defined grind attributes, a solver mode for bv_decide, and a first_par combinator that runs tactics in parallel. The release landed 309 changes, including performance improvements in bv_decide.

⊢Checked against: v4.28.0 release notes·lean4 v4.28.0

Lean core·Feb 16

Leo de Moura merges isDefEq transparency change into Lean core

The pull request stops isDefEq from raising transparency to .default when checking implicit arguments, which was creating scalability problems in Mathlib. The PR calls it a very disruptive change, reversible with set_option backward.isDefEq.respectTransparency false. Separately, Lean published the second release candidate for v4.29.0.

⊢Checked against: lean4#12179·lean4 v4.29.0-rc2

Lean core·Feb 15

Leo de Moura adds higher-order Miller patterns to grind's e-matching

A merged Lean 4 pull request lets grind's e-matching engine keep lambda arguments as patterns when pattern variables are applied only to distinct lambda-bound variables. Previously such lambdas were ignored during matching, which limited theorems about combinators like List.foldl that take a function argument.

⊢Checked against: lean4#12483

Lean core·Feb 12

Leo de Moura merges two Lean core elaborator changes

Leo de Moura merged a pull request stopping isDefEq from raising transparency to .default for implicit arguments, which was creating scalability problems in Mathlib (old behavior: set_option backward.isDefEq.respectTransparency false). A second pull request fixes the type class resolution cache for classes with output parameters.

⊢Checked against: lean4#12179·lean4#12286

Lean core·Feb 5

Leo de Moura's Lean change stops simp from simplifying instances by default

The pull request, merged on 2026-02-05, ensures simp does not "simplify" instances by default, since doing so creates non-standard instances that cause problems in Mathlib. The old behavior can be retrieved with simp +instances, and the backward compatibility flag for dsimp also deactivates the change.

⊢Checked against: lean4#12244

Lean core·Jan 29

Sebastian Ullrich's merged PR separates meta and non-meta code in Lean binaries

The change lets the module system, in cooperation with the linker, keep tactics used only in proofs out of the final native binary. A simple example using meta import Lean shrinks from 130MB to 1.7MB. As a breaking change, importModules (loadExts := true) must now be preceded by enableInitializersExecution.

⊢Checked against: lean4#12016

Lean core·Jan 28

Leo de Moura merges three Lean core changes to instance handling

Lean now identifies instance parameters by type using isClass? instead of binder syntax, dsimp no longer simplifies instances by default, and isDefEq no longer raises transparency to .default for implicit arguments, a change the PR calls very disruptive. Old behavior is available through backward.* options, and the PRs cite problems in Mathlib.

⊢Checked against: lean4#12172·lean4#12195·lean4#12179

Lean core·Jan 10

Sebastian Ullrich proposes bundling Lean's Init library into one .olean file

A pull request by Sebastian Ullrich bundles all Init module files into a single file with cross-sharing, reducing cumulative size from 325MB to 264MB and openat calls for import Init on Linux from about 2000 to about 80. The pull request is still open.

⊢Checked against: lean4#11965

Lean core·Dec 30

Leo de Moura adds benchmarks showing SymM beating MetaM on intros/apply

A merged Lean 4 pull request by Leo de Moura adds performance comparison tests between the new SymM monad and the standard MetaM for intros/apply operations. Results show a 10-20x speedup, rising from 10.8x at size 1000 to 22.0x at size 6000.

⊢Checked against: lean4#11838·leanprover/lean4

Lean core·Feb 5

Leo de Moura's Lean change stops simp from simplifying instances by default

The pull request, merged on 2026-02-05, ensures simp does not "simplify" instances by default, since doing so creates non-standard instances that cause problems in Mathlib. The old behavior can be retrieved with simp +instances, and the backward compatibility flag for dsimp also deactivates the change.

⊢Checked against: lean4#12244

Lean core·Jan 29

Sebastian Ullrich's merged PR separates meta and non-meta code in Lean binaries

The change lets the module system, in cooperation with the linker, keep tactics used only in proofs out of the final native binary. A simple example using meta import Lean shrinks from 130MB to 1.7MB. As a breaking change, importModules (loadExts := true) must now be preceded by enableInitializersExecution.

⊢Checked against: lean4#12016

Lean core·Jan 28

Leo de Moura merges three Lean core changes to instance handling

Lean now identifies instance parameters by type using isClass? instead of binder syntax, dsimp no longer simplifies instances by default, and isDefEq no longer raises transparency to .default for implicit arguments, a change the PR calls very disruptive. Old behavior is available through backward.* options, and the PRs cite problems in Mathlib.

⊢Checked against: lean4#12172·lean4#12195·lean4#12179

Lean core·Oct 12

Sebastian Ullrich removes Lean's 255-object-field limit per constructor

A merged pull request by Sebastian Ullrich removes the limit of 255 object fields per constructor, and thus per structure. When a constructor has more, the compiler keeps the first 254 in the constructor object and stores the rest in a chain of spill objects, with one pointer followed per spill object on access.

⊢Checked against: lean4#15516

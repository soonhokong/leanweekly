Lean core·Oct 20

Sebastian Graf merged vcgen +jp, which verifies code after a split once

Without +jp, vcgen copies the code after an if or a match into every branch, so the number of copies doubles with each consecutive split. With +jp, VC generation grows linearly with the number of splits, and the shared code is verified under a hypothesis stating what each branch knows at its end.

⊢Checked against: lean4#14398

Lean core·Oct 21

Leo de Moura adds three lia changes that avoid large case splits

The pull requests, merged October 20 and 21, add dynamic variable reordering before large Cooper splits (case splits with as many cases as a variable's coefficient), exact elimination of equations without unit coefficients, and divisibility normalization. Lean core·Oct 22

Sebastian Ullrich proposes precomputed prefix trees to speed up Lean imports

The open pull request replaces hash maps of imported constants, built eagerly at import time, with per-module prefix trees precomputed when oleans are written and merged lazily on first access. The change cuts import Lean wall-clock time by 28% and Mathlib's import phase by 21%, in exchange for about 6% larger standard library oleans.

⊢Checked against: lean4#14362

Lean core·Oct 19

The FRO noticed probabilistic segfaults while compiling big Lean projects on certain AMD CPUs running Linux 6.15 or later, and reported them to the Linux kernel.

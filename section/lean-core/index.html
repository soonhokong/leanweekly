Lean core·Nov 21

Joachim Breitner removes large elimination for recursive Prop inductives from Lean's kernel

The merged pull request, part of the Lean Kernel Renovation, restricts recursors such as Acc.rec to motives in Prop, while Eq and And keep large elimination. The goal is a kernel that never has to look at a proof term, which would let tools like external checkers drop proof subterms after typechecking.

⊢Checked against: lean4#13851

Lean core·Nov 16

Henrik Böving adds epr tactic for EPR, a first-order logic fragment

Merged into Lean as #16468, the tactic uses a BitVec encoding combined with bv_decide and performs about level with Z3 on the TPTP EPR benchmark set. On verification conditions from Veil, a protocol verifier, it solves 769 (97%) of the 792 that lie fully within EPR and 1,082 (71%) of all 1,512.

⊢Checked against: lean4#16468

Lean core·Nov 7

Sebastian Ullrich speeds up deriving Repr, BEq, and Hashable on mutual blocks

Lean now derives these classes once per mutual block, generating the auxiliary functions once for the whole block instead of once per type. This removes quadratic elaboration cost: deriving Repr on every type of a 76-type mutual block went from 309 seconds and 10.2 GB to 62 seconds and 1.3 GB.

Lean core·Oct 30

Leo de Moura fixes three quadratic performance issues in Lean

The issues include an Expr hash collision: chains of the same application with different lengths could share hashes, so kernel cache lookups compared them structurally and checks became quadratic. The other two are quadratic elaboration of large string-literal equalities and quadratic compilation of large list literals.

Lean core·Oct 20

Sebastian Graf merged vcgen +jp, which verifies code after a split once

Without +jp, vcgen copies the code after an if or a match into every branch, so the number of copies doubles with each consecutive split. With +jp, VC generation grows linearly with the number of splits, and the shared code is verified under a hypothesis stating what each branch knows at its end.

⊢Checked against: lean4#14398

Lean core·Oct 22

Sebastian Ullrich proposes precomputed prefix trees to speed up Lean imports

The open pull request replaces hash maps of imported constants, built eagerly at import time, with per-module prefix trees precomputed when oleans are written and merged lazily on first access. The change cuts import Lean wall-clock time by 28% and Mathlib's import phase by 21%, in exchange for about 6% larger standard library oleans.

⊢Checked against: lean4#14362

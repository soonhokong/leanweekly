Verification·Nov 13

okcontract publishes Solidity Spec, an executable formal model of Solidity in Lean

The Lean 4.29.0 package targets Solidity 0.8.36 and comes with a paper on its semantics and trust boundary. Conformance checks compare selected executions with the pinned compiler and a local Cancun EVM; okcontract calls the formalization incomplete and notes that compiler compatibility, scoped to viaIR: true, is not a proof of general compiler conformance.

⊢Checked against: okcontract/solidity-spec

Verification·Nov 13

mathematics-inc runs Linux's WireGuard handshake code in Lean, finding undefined behaviour

The repository holds the Cerberus Core of a program running a complete two-peer WireGuard handshake, as readable Lean modules with one definition per WireGuard C function. Running it under a C semantics in Cerberus-Lean produced output identical to an independent reference implementation and also found limitations of Cerberus and Cerberus-Lean.

⊢Checked against: mathematics-inc/wireguard-handshake-cerberus-lean

Verification·Nov 12

Bartosz Naskręcki publishes Lean Doom Lab, pairing Doom play with Lean proofs

Users can play a route, pause on a game tick and inspect its Lean proof; in a browser course of nine authored maps, all 27 supplied route witnesses have stock Lean kernel audits. The lab's first-safe-exit theorems state that the player remains alive, physics succeeds and the last input raises the exit flag.

⊢Checked against: nasqret/leandoom-proofs

Verification·Nov 10

AI-written Lean model of CPython 3.15.2 finds hundreds of bugs

David Andrews and Chao Zhang's model spans 613,318 lines of Lean with 18,898 theorems and lemmas; each modelled function must agree with the real interpreter on at least 50,000 cases. Of 26,004 functions in scope, 4,071 (15.7%) are judged faithful by independent review, and 418 bug records reproduce on 3.15.2, each with a reproducer.

⊢Checked against: Broyojo/python-formalization

Verification·Nov 8

Yalu Cai, Tung-Che Chang, and Santosh Nagarakatte verify an eBPF proof checker

Keel, an in-kernel proof checker for the Linux eBPF verifier, is specified in Lean and proved sound against bit-vector semantics; its implementation in EmbC, a deeply embedded C fragment, is proved to refine that specification. Formalizing the eBPF Certificate Framework (BCF) checker uncovered 13 bugs, and Keel runs 1.3X faster than BCF's checker.

⊢Checked against: arXiv:2611.11117

Verification·Nov 7

Andreas Andreakis extends DBLog to delete orphan rows, with Lean 4 proofs

DBLog-based incremental snapshots, adopted by Debezium and Flink CDC, originally did not handle orphan rows (in the sink, absent at the source); the extension deletes keys a chunk read did not return. Safety and convergence are proved in Isabelle/HOL and, except for the Flink CDC theory, in Lean 4, with no unfinished proofs.

⊢Checked against: arXiv:2611.10810·doi.org

Anthropic released FlashProve, which uses a zkSNARK (a type of cryptographic proof) to prove which AI model answered a request. Anthropic used Lean to specify FlashProve's protocol and prove completeness (honest proofs are accepted), soundness (fake proofs are rejected) and zero-knowledge (proofs hide the model's weights), and shipped an executable, provably correct Lean verifier.

Verification·Nov 2

Sreehari Sankar and coauthors present LeanGuard, Lean-verified guardrails for AI agents

LeanGuard checks every tool call an agent proposes against a Lean 4 policy, using a decision procedure proved equivalent to a LeanLTL temporal semantics. On Tau-Bench, unguarded Qwen agents executed at least 33 policy-forbidden calls while LeanGuard executed none, and it cut direct prompt-injection success on DTap from 57.9% to 5.9%.

⊢Checked against: arXiv:2611.02332·DebarghaG/LeanGuard

Verification·Oct 30

Jan Onderka, Armin Biere and Henrik Böving verify a Lean SMT-LIB parser

The paper introduces blazing-smtlib, a Rust parsing library for SMT-LIB (a standard input format for SMT solvers), and its Lean port BSmtLib, whose optimised lexer and parser provably match a formalised SMT-LIB syntax. On 9,201 benchmark files, blazing-smtlib is more than 6 times faster than previous libraries (geometric mean); BSmtLib is faster or comparable.

Verification·Nov 2

Sébastien Celles uses Lean 4 to find correctness bugs in Go

Inspired by julia-in-lean, the go-in-lean proof-of-concept models a bounded subset of Go (including all of math/bits), states each function's documented behaviour as a theorem, proves it with Lean's kernel and bv_decide, and turns failed proofs into Go tests. Counterexamples must reproduce in Go, and the README lists Go compiler bugs reported after human review.

⊢Checked against: s-celles/go-in-lean
